# Roadmap: живая деревня

**Статус:** план разработки, реализация не начата.  
**Среда:** сначала локально, серверное размещение позже.  
**Принцип:** небольшие завершённые шаги с проверкой и сохранением состояния.

## 1. Правила работы

1. За один рабочий заход брать один небольшой шаг или подэтап.
2. Перед началом читать `CONCEPT.md`, `ROADMAP.md` и `STATUS.md`.
3. Не считать этап завершённым без проверки критериев готовности.
4. После каждого шага обновлять `STATUS.md`:
   - что изменено;
   - какие проверки выполнены;
   - что не работает или не проверено;
   - ближайший следующий шаг.
5. Значимые решения фиксировать в `docs/DECISIONS.md`.
6. Не подключать платный LLM API без согласования провайдера и бюджета.
7. Сначала делать рабочий вертикальный срез, затем расширять мир.
8. Не усложнять архитектуру ради будущей MMO.

**Важно:** один этап roadmap может занимать несколько сессий. При остановке нужно оставлять воспроизводимое состояние, а не только объяснение в чате.

## 2. Общая последовательность

```text
Документация
    ↓
Минимальный локальный проект
    ↓
Время, действия и сохранение
    ↓
Автономная деревня
    ↓
Внешнее давление и распространение сведений
    ↓
Память и протокол рефлексии
    ↓
Реальная модель на двух персонажах
    ↓
Забывание и изменение ядра
    ↓
Проверка гипотезы и расширение
    ↓
Подготовка к серверу
```

Ключевая контрольная точка — **два NPC проходят полный цикл «событие → рефлексия → память → изменившееся решение»**. До этого не следует вкладываться в большой мир и сложный интерфейс.

**Цель:** сделать проект понятным без истории чата.

### Задачи

- [ ] Сохранить `docs/CONCEPT.md`.
- [ ] Сохранить `docs/ROADMAP.md`.
- [ ] Создать `docs/STATUS.md`.
- [ ] Создать `README.md` с порядком продолжения.
- [ ] Создать `docs/DECISIONS.md` для принятых решений.
- [ ] Зафиксировать рабочий каталог и границы проекта.

### Критерий готовности

Новая сессия может определить цель, фактическое состояние и ближайший шаг, прочитав документы.

### Точка остановки

Документация готова к просмотру пользователя. Код ещё не требуется.

## Этап 1. Минимальный локальный каркас

**Цель:** получить запускаемый проект с минимальной проверкой сервера и браузера.

### Задачи

- [ ] Проверить доступные версии Node.js и пакетного менеджера.
- [ ] Выбрать и зафиксировать совместимые версии инструментов.
- [ ] Создать TypeScript-проект с сервером и веб-интерфейсом.
- [ ] Добавить проверку работоспособности API.
- [ ] Показать в браузере состояние соединения с сервером.
- [ ] Настроить проверку типов и запуск тестов.
- [ ] Добавить `.gitignore` и инициализировать Git, если это уместно.
- [ ] Записать точные команды запуска и остановки.

### Критерии готовности

- Проект запускается локально по инструкции.
- Браузер получает ответ именно от сервера проекта.
- Проверка типов и минимальный тест проходят.
- Нет API-ключей и платных запросов.

### Точка остановки

Работает пустая оболочка приложения. Игровая симуляция ещё не реализована.

## Этап 2. Движок времени, действия и сохранение

**Цель:** создать надёжное основание симуляции без LLM.

### Задачи

- [ ] Определить минимальные сущности: мир, персонаж, локация, запас, событие.
- [ ] Ввести игровые дни и фазы дня.
- [ ] Реализовать явное продвижение времени.
- [ ] Определить порядок обработки действий и событий внутри фазы.
- [ ] Добавить очередь запланированных событий.
- [ ] Реализовать проверяемые действия: перемещение, получение и расход ресурса.
- [ ] Добавить SQLite, начальную схему и версию схемы.
- [ ] Сохранять состояние и журнал атомарно.
- [ ] Добавить создание нового мира и восстановление сохранённого.
- [ ] Использовать задаваемый seed для случайных событий.

### Критерии готовности

- Время продвигается только по заданным правилам.
- Запасы не становятся отрицательными.
- Невозможное действие отклоняется с объяснением.
- Перезапуск приложения сохраняет мир.
- Одинаковое начальное состояние, seed и команды дают одинаковый результат без LLM.

### Точка остановки

Маленький технический мир с несколькими сущностями. Без экономики деревни и личности.

## Этап 3. Автономная повседневная жизнь

**Цель:** деревня живёт без игрока и модели.

### Задачи

- [ ] Создать начальный набор жителей, хозяйств и локаций.
- [ ] Определить простые расписания и рабочие роли.
- [ ] Добавить производство, потребление и отдых в минимальном объёме.
- [ ] Ограничить доступный труд и добычу ресурсов.
- [ ] Ввести одну–три активные цели на персонажа.
- [ ] Добавить обязательства с получателем, сроком и состоянием исполнения.
- [ ] Предотвратить назначение несовместимых занятий одновременно.
- [ ] Сделать экран времени, жителей, запасов и журнала.
- [ ] Добавить прогон нескольких дней без ручного вмешательства.

### Критерии готовности

- Деревня проходит минимум две игровые недели без игрока.
- Запасы меняются по понятным причинам.
- Жители выполняют занятия и сталкиваются с ограничениями.
- Журнал позволяет объяснить результаты.
- Нет бесконечной добычи и скрытого создания ресурсов.

### Точка остановки

Рабочая хозяйственная симуляция. Поведение пока определяется кодом.

## Этап 4. Осеннее давление и внешний мир

**Цель:** получить ситуации, в которых возникает содержательный выбор.

### Задачи

- [ ] Определить вымышленный правовой уклад и получателя платежа.
- [ ] Задать стартовые запасы и срок осеннего платежа.
- [ ] Разделить ресурсы там, где это влияет на выбор: питание, посев, топливо, платёж.
- [ ] Добавить торговца с ограниченными товарами и деньгами.
- [ ] Добавить внешние события: новости, задержка обоза, ухудшение дороги или погоды.
- [ ] Задать условия, периодичность и последствия сценариев.
- [ ] Добавить источники сведений и доставку новостей.
- [ ] Отделить объективное событие от знания конкретного NPC.

### Критерии готовности

- Возникает хотя бы один конфликт между двумя выполнимыми, но несовместимыми целями.
- Внешнее событие действительно меняет условия жизни.
- NPC не узнаёт сведения без источника.
- Слух может быть ложным и не меняет объективные факты.
- Сценарий можно повторить с фиксированными условиями.

### Точка остановки

Мир способен создавать опыт для личности. Полноценная рефлексия ещё не требуется.

## Этап 5. Wiki-память и протокол изменений

**Цель:** реализовать механику памяти без платных запросов.

### Задачи

- [ ] Определить структуру ядра, недавнего опыта и значимых воспоминаний.
- [ ] Добавить отношения, убеждения, цели и текущее состояние.
- [ ] Связать записи памяти с исходными событиями и источниками знаний.
- [ ] Добавить версии и историю изменений.
- [ ] Определить структурированный ответ рефлексии.
- [ ] Реализовать проверку и атомарное применение предложенных изменений.
- [ ] Защитить от повторного применения одного результата.
- [ ] Отклонять предложения с неизвестными ссылками и устаревшими версиями.
- [ ] Создать детерминированный тестовый адаптер.
- [ ] Добавить просмотр и Markdown-экспорт wiki.

### Критерии готовности

- Тестовый результат рефлексии проходит весь путь до сохранённой памяти.
- Повторная обработка не удваивает влияние.
- Устаревшая правка не затирает новое состояние.
- Изменения можно проследить и восстановить.
- Факт, слух и интерпретация остаются различимыми.

### Точка остановки

Механика памяти работает. Качество реальной модельной личности ещё не проверено.

## Этап 6. Вертикальный срез с реальной моделью

**Цель:** проверить основную гипотезу на двух персонажах до расширения системы.

### Перед началом согласовать

- Провайдера и модель.
- Способ хранения ключа.
- Допустимый бюджет эксперимента.
- Лимиты запросов и контекста.
- Какие данные передаются внешнему провайдеру.

### Задачи

- [ ] Подключить реальный LLM-адаптер; по умолчанию оставить тестовый режим.
- [ ] Создать два различающихся ядра персонажей.
- [ ] Реализовать сборку релевантного контекста.
- [ ] Добавить выбор намерения из допустимых действий.
- [ ] Добавить рефлексию после значимой сцены.
- [ ] Ограничить параллельность, повторы и время ожидания.
- [ ] Учесть использование токенов и стоимость при известных тарифах.
- [ ] Обработать сбои и невалидные ответы без повреждения мира.
- [ ] Показать цепочку от события до нового решения.
- [ ] Добавить минимальное взаимодействие игрока: диалог и один материальный поступок.

### Критерии готовности

- Одно событие получает различный, согласованный с ядром смысл у двух NPC.
- Хотя бы одно изменение памяти влияет на последующее решение.
- Сервер отклоняет невозможные действия модели.
- Бюджет соблюдается; число повторных запросов ограничено.
- При ошибке API состояние остаётся корректным.
- Человек может объяснить поведение по сохранённой причинной цепочке.

### Контрольная точка

**Решить, подтверждается ли идея.**

Если поведение непоследовательно, сначала исправить контекст, промпты и протокол памяти. Не компенсировать проблему увеличением числа NPC.

## Этап 7. Забывание и консолидация

**Цель:** память ограничена, но развитие героя не сбрасывается.

### Задачи

- [ ] Ввести настраиваемые бюджеты уровней памяти.
- [ ] Определить критерии отбора кандидатов на забывание.
- [ ] Реализовать сжатие нескольких эпизодов в общий результат.
- [ ] Проверять основания выводов после удаления деталей.
- [ ] Ввести лимит 32 подробных профилей знакомых.
- [ ] Определить защиту важных связей без возможности защитить всё.
- [ ] Решить, как хранить краткие следы забытых знакомых.
- [ ] Отделить изменение отношений от изменения общего характера.
- [ ] Добавить отдельный проверяемый путь правки ядра.
- [ ] Проверить пересмотр старой интерпретации при новых сведениях.

### Критерии готовности

- Переполнение приводит к управляемому сжатию или вытеснению.
- Накопленное доверие не исчезает вместе с деталями встреч.
- Лимит знакомых соблюдается на тесте с более чем 32 участниками.
- Незавершённые обязательства не теряются при забывании.
- Каждая правка ядра имеет объяснение и предыдущую версию.
- Консолидация не превращает предположение в факт.

### Точка остановки

Полный цикл ограниченной долговременной памяти работает на небольшой группе.

### Задачи

- [ ] Расширить до согласованного числа жителей.
- [ ] Добавить инициативы NPC и взаимодействия между ними.
- [ ] Сделать понятные карточки персонажей и локаций.
- [ ] Добавить действия игрока с реальной ценой и последствиями.
- [ ] Разделить игровой режим и отладочный просмотр.
- [ ] Не показывать игроку скрытые знания через обычный интерфейс.
- [ ] Добавить управление очередью, паузу и ускорение.
- [ ] Сделать сохранение, загрузку и сброс с подтверждением.
- [ ] Показывать режим LLM и расход бюджета.
- [ ] Прогнать осенний сценарий до срока платежа и после него.

### Критерии готовности

- Пользователь может играть и наблюдать без обращения к базе вручную.
- Отсутствие игрока не останавливает жизнь.

- Ускорение не запускает неограниченное число запросов.
- Платёж имеет реальные последствия для хозяйства и отношений.

### Точка остановки

Локальный MVP пригоден для длительного тестирования.

## Этап 9. Оценка качества и стабилизация

**Цель:** отделить рабочую гипотезу от отдельных удачных диалогов.

### Задачи

- [ ] Подготовить повторяемый набор сценариев из CONCEPT.
- [ ] Сравнить статическую личность с личностью, использующей рефлексию.
- [ ] Раздельно оценить корректность симуляции и качество отыгрыша.
- [ ] Проверить жизнь без игрока, слухи, накопление опыта и забывание.
- [ ] Проверить устойчивость к игровым репликам, требующим переписать системные правила.
- [ ] Проверить перезапуск при незавершённых модельных задачах.
- [ ] Измерить число запросов, токены, задержки и рост базы.
- [ ] Ввести политику хранения подробных логов.
- [ ] Зафиксировать ограничения и известные проблемы.
- [ ] Подготовить демонстрационный сценарий.

### Критерии готовности

- Есть отчёт с примерами успехов и неудач.
- Технические инварианты покрыты тестами.
- Психологические оценки не подменяются только успешностью JSON-валидации.
- Понятна стоимость игрового дня при выбранных настройках.
- Есть основания решать, стоит ли расширять проект.

### Точка остановки

Принять решение: улучшать текущую модель, расширять мир или пересматривать подход.

## Этап 10. Подготовка к серверному размещению

**Цель:** перенести проверенный локальный MVP без преждевременного усложнения.

### Задачи

- [ ] Проверить сборку и запуск на Linux.
- [ ] Вынести конфигурацию и секреты из исходников.
- [ ] Настроить постоянное хранение базы.
- [ ] Добавить HTTPS и ограничение доступа к тестовому миру.
- [ ] Закрыть отладочные и административные операции.
- [ ] Настроить перезапуск процесса и проверку работоспособности.
- [ ] Сделать резервное копирование и проверить восстановление.
- [ ] Определить поведение игрового времени при остановке сервера.
- [ ] Провести нагрузочную проверку на предполагаемом VPS.
- [ ] Записать инструкцию развёртывания и обновления.

### Критерии готовности

- Мир переживает перезапуск сервера без повреждения.
- Секреты недоступны браузеру и не попадают в репозиторий.
- Бэкап восстанавливается в проверенный рабочий мир.
- Расходы ограничены.
- Характеристики сервера выбраны по измерениям, а не только предварительной оценке.

## 3. Что не делать до проверки гипотезы

- Не строить MMO.
- Не добавлять большой процедурный мир.
- Не начинать с десятков модельных NPC.
- Не отправлять всю wiki в каждый запрос.
- Не внедрять микросервисы и распределённые очереди без необходимости.
- Не создавать сложную графику вместо инструментов наблюдения.
- Не генерировать драму только ради заполнения памяти.
- Не обещать психологическую последовательность на основании одного удачного диалога.

## 4. Формат завершения каждой сессии

В `STATUS.md` оставлять:

```markdown
# Состояние проекта

## Текущий этап
Номер этапа и конкретный подэтап.

## Сделано
Только реально выполненное.

## Изменённые файлы
Пути и краткое назначение.

## Проверки
Команды, результаты, ручные проверки.
Отдельно — что не проверено.

## Запуск
Актуальные команды и адрес приложения.
Если запуска ещё нет — прямо указать это.

## Проблемы и ограничения
Ошибки, незавершённые части, принятые компромиссы.

## Следующий шаг
Одна конкретная задача с критерием готовности.

## Требуется решение пользователя
Только вопросы, действительно блокирующие ближайший шаг.
```

## 5. Ближайший шаг

**Сохранить документацию проекта и подготовить передачу между сессиями — этап 0.**

После этого отдельно перейти к минимальному локальному каркасу. Пока не устанавливать зависимости, не запускать сервер и не подключать платную модель.
