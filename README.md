# Живая деревня

Локальный веб-MVP автономных NPC с wiki-памятью, рефлексией и постепенно меняющимся характером.

Мир — деревня на тракте, вдохновлённая XIII–XIV веками. Осень, урожай в основном собран, приближаются обязательные платежи и зима. Жители ведут хозяйство, взаимодействуют и сталкиваются с последствиями своих решений независимо от присутствия игрока.

## Цель

Проверить, может ли система избирательной памяти и рефлексии создавать узнаваемых, последовательных и развивающихся персонажей.

Основной цикл:

```text
Жизнь мира → событие → восприятие NPC → рефлексия
→ изменение памяти → последующие решения
```

**Код обеспечивает факты и правила мира. Модель определяет личный смысл опыта и предлагает решения и изменения памяти.**

## Текущее состояние

Этапы 1–5 реализованы для локального MVP: каркас, движок, автономная деревня, внешний мир и wiki-память v5 с версиями, атомарными reflection proposals, JSON/Markdown API и Wiki-панелью.

- Typecheck проходит, тесты 34/34, production build проходит.
- Миграция v4→v5 проверяется тестом на сохранение старых знаний.
- Визуальный осмотр Wiki-панели в браузере остаётся рекомендованной QA-проверкой.
- Память пока не используется симуляцией для выбора действий; автоматическое скользящее окно и консолидация не реализованы.
- LLM API не подключён; платные запросы не выполняются.

Актуальный статус и следующий шаг — в `docs/STATUS.md`; модель памяти — в `docs/MEMORY_MODEL.md`.

## Продолжение в другой сессии

1. Прочитать `README.md` и `docs/STATUS.md`.
2. Прочитать `docs/CONCEPT.md`.
3. Найти текущий этап в `docs/ROADMAP.md`.
4. Проверить относящиеся к следующему шагу решения в `docs/DECISIONS.md`.
5. Проверить реальные файлы и доступные инструменты.
6. Выполнить один небольшой подэтап.
7. Проверить результат.
8. Обновить состояние и отметки roadmap.

Не считать запланированное реализованным. Если файл, команда или результат отсутствуют — явно указать это.

## Правила разработки

- Работать небольшими проверяемыми шагами.
- Сначала реализовать полный цикл на двух персонажах, затем расширять мир.
- Сохранять состояние так, чтобы работу мог продолжить другой агент.
- Фиксировать команды проверки и их результаты.
- Отдельно отмечать непроверенные части.
- Не усложнять архитектуру ради будущей MMO.
- Не скрывать сбои модели за случайными решениями.
- Не подменять оценку качества личности успешной проверкой формата ответа.

## Предварительный стек

- TypeScript / Node.js.
- Fastify — HTTP API.
- SQLite — состояние, память, журнал и задачи.
- React — веб-интерфейс.
- Внешний LLM API через сменный адаптер.

Текущий каркас использует этот стек. Детерминированный тестовый адаптер не вызывает LLM; реальный провайдер и бюджет пока не выбраны.

## Запуск и проверки

Требования: Node.js 24+ и npm 11+ (проверено на Node v24.21.0, npm 11.19.0).

```text
# установка зависимостей
npm install

# проверка типов
npm run typecheck

# запуск тестов
npm test

# сборка интерфейса
npm run build

# запуск сервера (http://127.0.0.1:3001)
npm run dev:server

# запуск интерфейса (http://localhost:5173, прокси /api на сервер)
npm run dev:web
```

Проверка API: `GET http://127.0.0.1:3001/api/health`.

Остановка — прервать соответствующий процесс (Ctrl+C).

База SQLite хранится в `data/village.db` (переопределяется переменной `DB_PATH`). Каталог `data/` в `.gitignore`.

## Работа с файловыми инструментами

В предыдущих попытках записи возникала ошибка из-за неверного использования параметра повышения доступа. Это не доказывает проблему с каталогом или правами файловой системы.

Правила для следующей сессии:

- Обычные вызовы `write`, `edit` и `pwsh` выполнять **без** полей `sandbox_permissions` и `justification`.
- Эти поля предназначены только для разрешённого повышения доступа после реального отказа sandbox.
- Если запросы разрешения отключены, повышение доступа не запрашивать.
- Ошибку `not strictly wider` не исправлять повторением тех же параметров.
- Перед изменением существующего файла читать его через `read`.
- Для новых файлов использовать `write`, для точечных изменений — `edit`.
- Всегда учитывать актуальную политику текущей сессии.

Файловая структура уже создана; перед изменением существующего файла сначала прочитать его.
